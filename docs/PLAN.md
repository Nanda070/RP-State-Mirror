Проект для сервера **Mirror** (GTA5RP): Discord-бот и веб-дашборд для государственных фракций.
Название в интерфейсе: «Mirror · GTA5RP». Язык — русский, время — МСК везде.

Проект новый: старые данные не переносятся. Python-бот, служивший справкой по поведению и форматам сообщений, удалён из репозитория 3 октября 2026 года.

## 1. Принципы

1. **Всё управляется через дашборд.** Конфигурация (серверы, фракции, роли, каналы, вебхуки, пинги, сроки, права, тексты) и любое действие любого модуля — нынешнего, будущего или существующего только в боте — доступны из дашборда. Любое сообщение бота с кнопками можно отправить и переотправить из дашборда. В коде нет ни одного ID.
2. **В `.env` только секреты и bootstrap-доступ:**
   - `DISCORD_BOT_TOKEN`
   - `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `OAUTH_REDIRECT_URL`
   - `DATABASE_URL`, `SESSION_SECRET`
   - `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`
   - `PUBLIC_BASE_URL` — адрес дашборда, по которому бот строит ссылки на веб-формы; по умолчанию `http://localhost:3000`, после появления домена меняется здесь
   - `SUPER_ADMIN_USER_IDS` — Discord ID главных админов, которые имеют полный доступ всегда, даже если главный сервер ещё не настроен или недоступен. По умолчанию `1219803151180370021`.
3. **Ничего не удаляется физически.** Только статусы (`active / closed / expired / revoked / archived`) и soft-delete.
4. **Полный аудит.** Любое действие (бот, дашборд, фоновая задача) пишется в `audit_log`: кто, когда, откуда (IP / сервер / канал), что было до, что стало после.
5. **Бот и дашборд — один домен, одна БД.** Бизнес-логика в общем слое, бот и дашборд только её вызывают.

## 2. Архитектура

**Стек:** TypeScript везде, монорепозиторий (pnpm workspaces).

| Часть | Технология |
|---|---|
| Бот | `discord.js` |
| Дашборд + API | Next.js (App Router), вход через Discord OAuth (Auth.js) |
| БД | PostgreSQL + Prisma (схема, миграции, типы) |
| Файлы | S3-совместимое хранилище (SeaweedFS) на том же VPS |
| Валидация | `zod` (общие схемы для бота, API и форм) |
| UI | Tailwind + shadcn/ui, адаптивная вёрстка |
| Задачи дашборд → бот | таблица `jobs` в PostgreSQL (позже при необходимости Redis) |

```
mirror/
  packages/
    core/      домен: сервисы, правила, права, аудит
    db/        Prisma-схема, миграции, клиент
  apps/
    bot/       Discord-бот: slash-команды, кнопки, модалки, фоновые задачи
    dashboard/ Next.js: веб-интерфейс + API
  docs/
```

- **Связь дашборд → бот:** очередь задач (например «опубликовать форму через вебхук», «выдать роли на всех серверах»). Бот исполняет, результат пишет в аудит.
- **Кэш конфигурации в боте** с инвалидацией при изменении в дашборде — без перезапуска.
- **Файлы:** все фото (ТС, униформа, документы переводов) бот скачивает из Discord и сохраняет в S3-хранилище, потому что ссылки на вложения Discord истекают. Превью и сжатие при загрузке.

## 3. Пользователи, персонажи, уровни доступа

### Аккаунт и персонажи
- Один Discord-аккаунт — **до 3 персонажей**.
- У каждого персонажа свой **статик**. Статик вводит сам игрок, админ может исправить.
- Один статик привязан **только к одному** Discord-аккаунту. Перенос на другой аккаунт выполняет администратор вручную (раздел 14.4 п.7); самостоятельного восстановления аккаунта нет.
- На персонажа: **1 нашивка**, **1 зарегистрированное ТС**.

### Откуда бот знает, кто есть кто

Бот не хранит «кто кем является» вручную — он читает роли на серверах Discord по правилам из дашборда.

| Что | Источник | Настройка в дашборде |
|---|---|---|
| Уровень админа (Главный / Старший / Админ / Хелпер) | роли на **главном сервере** | «Главный сервер» + роль → уровень |
| Должность админа | назначается в дашборде | список должностей |
| Членство во фракции | роль фракции на **сервере фракции** | сервер фракции + роль сотрудника |
| Лидер / заместитель | роль на сервере фракции | роль лидера, роль зама |
| Отдел | роли на сервере фракции | роль → отдел |
| Ранг | роли на сервере фракции | роль → номер ранга |
| Спецроли (ОГП, Юстиция и т. п.) | роли на сервере GOV | роль → право |
| Статик, персонажи | вводит игрок, правит админ | — |

- **Главный сервер** — поле в настройках дашборда. Только с него берутся уровни доступа к админке. **Сервер ЧП** — отдельный сервер и отдельное поле в настройках: на нём работают синхронизация ролей, розыск, регистрации ТС и униформы. Уровни доступа с него не берутся.
- Роли читаются в реальном времени: бот слушает изменения ролей и входы / выходы на всех подключённых серверах и обновляет снимок в БД (`discord_guild_members`). Раз в час — полная сверка на случай пропущенных событий.
- Права в дашборде и в командах проверяются по этому снимку, поэтому снятие роли в Discord сразу отнимает доступ.
- Пока главный сервер не настроен, в дашборд может войти только пользователь из `SUPER_ADMIN_USER_IDS` — он и делает первичную настройку.

### Уровни доступа

| Уровень | Откуда | Что может (по умолчанию) |
|---|---|---|
| Главный админ | `SUPER_ADMIN_USER_IDS` или роль главного админа на главном сервере | всё: настройки системы, админ-роли на серверах, управление админами, аварийная блокировка |
| Старший админ | роль на главном сервере (сопоставление в дашборде) | всё по данным и модерации, управление админами и хелперами, без системных настроек |
| Админ | роль на главном сервере | данные, модерация заявок, штрафы, розыски, нашивки, формы, embed-менеджер |
| Хелпер | роль на главном сервере | просмотр, обработка простых заявок, обратная связь, FAQ |
| Лидер фракции | роль лидера, настроенная в дашборде | заявки на перевод, кадровый аудит и данные своей фракции |
| Сотрудник | роли фракции из дашборда | slash-команды согласно матрице прав |
| Игрок | любой вошедший через Discord | свои персонажи, заявки, штрафы, розыски, публичные разделы |

Точные права каждого уровня — матрица «действие / раздел → уровни и роли», настраивается главным админом в дашборде.

### Фракции
FIB, GOV, LSPD, ARMY, SASPA, LSSD, EMS, WN (Weazel News). Добавление, переименование, отключение фракций, их цвет и эмодзи — в дашборде.

## 4. Модули бота

### 4.1 Документооборот
- Отправка документов и реестр (архив). **Не** шаблоны и не генерация документов — это отдельные системы сообщений/эмбедов.
- `/пост` — документ во фракцию через её вебхук, пинг лидера.
- `/ответ` — ответ в GOV через вебхук, пинг автора.
- Через 72 ч (настраивается) документ получает статус `expired`, запись остаётся в архиве.

### 4.2 Федеральный розыск
- `/объявить-розыск` → вебхук в канал ЧП.
- `/розыск-исполнено` → редактирование исходного сообщения + доказательства.
- В дашборде: список, поиск по статику, ручное закрытие / отмена.
- Игрок видит розыски по своим статикам в профиле.

### 4.3 Штрафы
- `/штраф`, `/штраф-оплачено`, уведомление о просрочке.
- Сумма — число (статистика, итоги).
- В дашборде: сделать неактуальным, отменить, изменить сумму, отметить оплату.
- Игрок видит штрафы по своим статикам в профиле и получает уведомление о новом штрафе.

### 4.4 Нашивки `/нашивка`
- Номер **уникален глобально**, освобождённые номера не переиспользуются автоматически. Номер хранится строкой.
- Длина растёт автоматически: сначала случайные 4 цифры (1000–9999). Когда свободных остаётся меньше порога (по умолчанию 10 %, настраивается), новые номера выдаются из 5 цифр, затем из 6. Выданные номера не меняются.
- Пользовательских slash-команд `/персонаж` нет: персонаж создаётся автоматически при выдаче нашивки по статику.
- `/нашивка получить` — выдаёт номер нашивки персонажу (только номер, без фракции/отдела). Командой или кнопкой на закреплённом сообщении. До 3 на аккаунт (по одной на персонажа).
- `/нашивка список` — все нашивки пользователя с датой получения (`issuedAt`); отозванные показываются со статусом. Ник бот **не меняет**.
- `/нашивка снять <номер>` — **только админы**.
- `/нашивка найти <номер | discord id | статик>` — карточка владельца. Доступно ролям **ОГП** и **Юстиция** на сервере GOV (список ролей настраивается в дашборде) и админам.

### 4.5 Регистрация ТС `/регистрация-тс`
1. Игрок вводит статик, модель (свободный текст; каталог ТС в дашборде — справочный), госномер, прикладывает фото.
2. Проверки: по статику нет активной регистрации этого типа; госномер не занят другой активной регистрацией; статик не под техническим баном.
3. Бот создаёт ветку в канале ЧП, публикует данные и фото, кнопки «Одобрить / Отказать», пинг администрации.
4. Первое нажатие засчитывается, кнопки сразу блокируются — двойного решения не бывает.
5. Одобрение → сообщение заменяется краткой карточкой.
6. Отказ → админ вводит причину в модалке, бот пишет её в ветку и игроку в личку.
7. Через 31 день (настраивается) запись помечается неактуальной, карточка редактируется, игрок получает уведомление. Регистрирует заново при необходимости.

### 4.6 Регистрация униформы `/регистрация-формы`
Тот же движок заявок, что и ТС, свои поля.

### 4.7 Запрос вебхука и формы `/создать-вебхук`
1. Сотрудник указывает канал и описание: для чего нужна форма.
2. Бот сам создаёт вебхук в канале (нужно право Manage Webhooks) и сохраняет его в конфиг.
3. Админам приходит уведомление в дашборде: «нужно создать форму» с описанием и уже привязанным вебхуком.
4. Админ собирает форму в конструкторе — она сразу привязана к этому вебхуку.

### 4.8 Перевод между фракциями `/перевод-фракции`
- Из, в, ранг, фото документов. Ранг проверяется по таблице переводов.
- Заявка в канал `transfers.channelId` с пингом ролей из `transfers.pingRoleIds`.
- Нужно одобрение **обеих** сторон (текущей и принимающей фракции). Отказ любой из них закрывает заявку с причиной. Автор заявки решение по ней принять не может.
- После одобрения игрок получает в личку сообщение: может подойти в холл на собеседование (текст настраивается). Роли бот не меняет.
- Заменяет старый `/аудит-перевод-фракция`.

### 4.9 Синхронизация доступов ЧП
Роли ЧП по фракционным ролям, автокик без фракции. Исключения и маппинг ролей — из дашборда.

### 4.10 Кадровый аудит
- Повышение, увольнение, перевод по отделу, восстановление, назначение.
- Оформляется и командой в Discord, и из дашборда (раздел «Персонал»): выбрать сотрудника, действие, детали — бот публикует запись в канал фракции.
- Каждая запись хранится в БД, её можно отредактировать, отозвать, переотправить; кнопка «Кикнуть» после увольнения доступна и в дашборде.
- Каналы, права и шаблоны — из дашборда.

### 4.11 Служебные утилиты
- `/проверить-фракции` — пересечения состава.
- `/инвайт-админ` — временные инвайты. Список серверов из дашборда.

### 4.12 Глобальные admin-роли (только дашборд)
- Slash-команд нет.
- Главный админ выбирает пользователя → выдать / снять роли на всех серверах, отчёт по каждому серверу.

### 4.13 Чёрный список (IC)
- Внутриигровой чёрный список граждан, ведёт GOV (аналог федерального розыска).
- Добавление: `/чс-гос` (ФИО, паспорт, причина, ссылка_на_форум) — номер и статус генерирует система; публикация embed в канал из настроек.
- Снятие: `/снятие-чс-гос` (номер, причина) — статус «Снят», правка исходного сообщения.
- Права: роли `icBlacklist.managerRoleIds` / поиск `searchRoleIds`; реестр и настройки в дашборде.
- Поиск `/чс-найти` по паспорту; игрок видит пометку в профиле дашборда, если паспорт совпадает со статиком.
- Список **информационный**: ничего в системе не блокирует (регистрации ТС, переводы, нашивки работают как обычно).
- Отдельно от него — технический бан на использование бота и форм (раздел 6), его ставят только админы.

### 4.14 Сообщения с кнопками в Discord
Конструируются в embed-менеджере (раздел 5.10) и публикуются ботом в любой канал:
- **Получение ролей:** кнопки или выпадающий список, роль выдаётся / снимается по нажатию; ограничения (кто может нажимать, взаимоисключающие роли).
- **Формы внутри Discord:** кнопка открывает модалку с полями из конструктора форм; ответ сохраняется в БД и уходит в выбранный канал / вебхук.
- **Обратная связь:** кнопка → модалка с категорией и текстом → тикет в дашборде и в канале; админ отвечает из дашборда, ответ приходит игроку в личку.
- **Служебные кнопки модулей** (`нашивка получить`, регистрации, заявки на перевод и т. д.) — тоже через менеджер.

Любое такое сообщение можно переотправить, отредактировать или удалить из дашборда; бот хранит ID сообщения и продолжает обрабатывать кнопки после перезапуска.

## 5. Дашборд

### 5.1 Доступ
- Вход только через Discord OAuth. Уровень определяется по ролям на главном сервере (раздел 3).
- **Игрок:** обзор, свой профиль и персонажи, каталог ТС, калькулятор переводов, FAQ, документация, свои заявки, штрафы и розыски.
- **Админ / лидер / главный админ:** по матрице прав.

### 5.2 Админские разделы
Обзор, документы, розыски, штрафы, нашивки, ТС, униформа, переводы, запросы вебхуков, конструктор форм, embed-менеджер, обратная связь, персонал (кадровый аудит), пользователи и персонажи, IC чёрный список, технические баны, журнал аудита, статистика админов, настройки.

Везде: поиск, фильтры, история изменений записи, редактирование, смена статуса, экспорт в CSV / Excel.

**Настройки** (главный админ): серверы, фракции, роли, каналы, вебхуки, матрица прав, сроки (72 ч, 31 день, порог нашивок), шаблоны сообщений бота, должности админов, список админов, юридические тексты.

### 5.3 Разделы для игроков
- **Каталог разрешённых моделей ТС:** карточки с фото, марка, год, поиск, фильтр по марке, «скопировать». Админы редактируют. Каталог справочный: на `/регистрация-тс` не влияет, модель в команде — свободный текст.
- **Калькулятор переводов:** таблица соответствия рангов между фракциями — попарные правила «фракция A, ранг N → фракция B, ранг M». Редактирует главный админ, используется в `/перевод-фракции`; пара без правил ранг не проверяет.
- **FAQ и документация:** редактируются в дашборде, с поиском.
- **Обзор:** статистика и графики.
- **Темы:** пресеты и свой цвет акцента.

### 5.4 Профиль пользователя

**Статус человека** (крупный бейдж под именем):
- **Админ** — должность («Главный администратор», «Старший администратор», «Куратор фракций»…). Должности, порядок, цвет, иконка — в дашборде.
- **Игрок** — фракция в её цвете, отдел и ранг: `LSPD · Отдел · Ранг 5`.
- Админ во фракции — главным показывается должность, фракция вторым бейджем.
- Ни должности, ни фракции — «Гражданин».

**Из Discord** (обновляется при входе и событиями бота):
- аватар (включая GIF), баннер, цвет акцента, рамка аватара;
- отображаемое имя, username, ID, дата создания, значки;
- по каждому серверу фракции: ник, серверный аватар, роли с цветами, дата входа, статус в сети.

**Из проекта:** персонажи (статик, ник, фракция, отдел, ранг), нашивки, ТС и униформа, переводы, штрафы, розыски. Для админов дополнительно: кадровые события, полная история из `audit_log`.

**Вид:** шапка с баннером (или градиент из цвета акцента), аватар с рамкой и индикатором статуса, бейджи; вкладки «Обзор», «Персонажи», «Нашивки», «Регистрации», «Штрафы и розыск», «Фракции и роли», «История».

**Технически:** OAuth-скоупы `identify` + `guilds.members.read`; снимок данных в `discord_profiles`, обновление на событиях `userUpdate` / `guildMemberUpdate`.

### 5.5 Конструктор форм
- Форма как в Google Forms: поля, типы, обязательность, валидация. Типы: короткий текст, абзац, число, выбор одного, выбор нескольких, флажок, дата. Загрузки файлов нет.
- Привязка к Discord-вебхуку (в том числе созданному через `/создать-вебхук`).
- Заполнение на публичной странице **без входа**, ответ уходит через вебхук; админы видят все ответы.
- Ограничения: срок жизни и лимит ответов у формы. Капча, лимит с IP и блокировка IP не делаются (решение от 2026-10-03).

### 5.10 Embed-менеджер и конструктор сообщений
- Отправка сообщений и embed'ов **от лица бота** (или через вебхук с именем и аватаром) в любой канал любого сервера.
- Два режима: классические embed'ы (до 10 штук, все поля) и **Discord Components V2** (контейнеры, секции, текстовые блоки, медиа-галереи, разделители, файлы, кнопки, выпадающие списки).
- Визуальный редактор с живым превью в стиле Discord, импорт / экспорт JSON.
- Шаблоны: сохранить, дублировать, использовать в модулях; переменные (`{user}`, `{faction}`, `{token}` и т. д.).
- Отправленные сообщения: список, редактирование на месте, переотправка, удаление, планирование отправки.
- Сюда же — шаблоны всех системных сообщений бота (документы, розыски, штрафы, регистрации, аудит).
- Загрузка уже существующего сообщения в редактор по ссылке (канал + ID сообщения), правка и сохранение на месте.

**Что берём из Cheterin Bot Dashboard** (`bot/core/components_v2.py`, `embed_builder.py`, `message_template_core.py`, `dashboard/backend/routes/embed_builder.py`, `bot/modules/utility/button.py`):
- единая JSON-спецификация сообщения, одна и та же в редакторе, БД и боте;
- проверка лимитов Discord до отправки (заголовок 256, описание 4096, до 25 полей, значение поля 1024, всего 6000 символов);
- переключатель V1 / V2 на уровне сообщения;
- постоянные кнопки через `custom_id` с префиксом и общий обработчик нажатий — работают после перезапуска;
- кнопки ролей: переключение (выдать / снять), кулдаун, проверка, что роль ниже роли бота и не управляемая, лог;
- кнопка-форма открывает модалку, ответы уходят в канал / вебхук;
- подстановка переменных `{name}` во все текстовые поля;
- разбор существующего сообщения (в том числе V2) обратно в редактор.

**Что делаем лучше:**
- V2 — полноценный редактор дерева компонентов, а не конвертация embed'а в V2;
- `custom_id` вида `mirror:<действие>:<id>`, действие и параметры хранятся в БД, а не зашиты в строку;
- до 25 кнопок и выпадающие списки ролей вместо 5 кнопок;
- формы любой длины: больше 5 полей — несколько шагов модалки; типы полей и валидация из конструктора форм;
- шаблоны и сообщения в PostgreSQL без лимита в 50, с историей версий и аудитом.

## 6. Безопасность и надёжность

Сделано в этапе 6 (2026-10-03).

- **Сессии:** каждый вход — строка в таблице `sessions`, её id лежит в cookie; запрос принимается, пока строка не завершена. Пользователь видит свои сессии в профиле (вкладка «Сессии»), завершает любую или все, кроме текущей. Главный админ видит и завершает чужие (`/settings/sessions`).
- **Журнал входов:** IP, устройство, время входа и последней активности — те же строки `sessions`.
- **Аварийная кнопка** (`Настройки → Система`): закрывает команды, кнопки и формы бота, дашборд, публичные формы и публичные ссылки для всех, кроме главных админов. Фоновая работа (синхронизация ЧП, очередь задач, истечение сроков) продолжается. Срабатывает в течение 10 секунд.
- **Технический бан** (`/bans`, не путать с IC чёрным списком): по Discord ID — запрет команд и кнопок бота и входа на сайт, открытые сессии завершаются сразу; по статику — отказ в заявках (нашивка, регистрации, перевод). Ставят «Админ» и выше. Главного админа и самого себя забанить нельзя. Бан по IP не делается (решение 2026-10-03).
- **Защита:** проверка прав на сервере для каждого действия; публичные формы принимают запросы только со своего адреса; кулдаун на кнопки бота.
- **Мониторинг:** состояние служб (бот, очередь задач, БД, хранилище, резервные копии) — командой `update.sh status`; страница `/status` удалена по решению владельца 3 октября 2026; ошибки бота и задачи, упавшие после всех попыток, — в служебный канал; если бот молчит дольше 90 секунд, сайт отправляет одно оповещение на вебхук. Канал и вебхук задаются в `Настройки → Система`.
- **Бэкапы:** сервис `backup` в Docker Compose: ежедневно в 04:00 дамп PostgreSQL (хранится 14 дней) и копия S3-хранилища на отдельный том; `verify.sh` проверяет восстановление во временную базу, `restore.sh` восстанавливает. Результат каждой копии виден на странице статуса.
- **Журнал аудита:** не удаляется; записи старше `audit.archiveAfterDays` (365 дней) бот переносит в `audit_log_archive`.
- **Экспорт:** каждый реестр выгружается в CSV (кнопка «Скачать CSV»), выгрузка пишется в аудит.
- ~~Статистика админов (`/stats`)~~ — страница и модуль удалены по решению владельца 3 октября 2026.
- **Роли администрации** (`Фракции → Роли администрации`): набор ролей на каждый уровень для каждого сервера; выдача или снятие уровня сразу на всех серверах с отчётом по каждому.

Редактирование включается кнопкой справа сверху; кнопку видит вошедший администратор («Админ» и выше, хелперы — нет).

Условия владельца: только открытое ПО; без водяных знаков; без чужих логотипов, значков и подписей в интерфейсе.

### 17.1 Что нужно на самом деле

Владелец уточнил объём и дал два образца — «Реестр организаций» и «Реестр частных адвокатов Mirror» (Google Sheets). В образцах:

- обычные реестры: текст, номера, даты; около 500–1000 строк и 10–14 столбцов; один-два листа;
- закреплённая шапка, объединённые строки-заголовки разделов;
- оформление: свой шрифт (Montserrat), тёмный фон, цветные заливки, границы, ширины столбцов;
- выпадающий список с цветными плашками («Статус лицензии»), флажки («Статус», «❄»);
- картинок, ссылок, диаграмм и сводных в образцах нет.

**Не нужно** (решение владельца): расширения, инструменты, диаграммы, сводные таблицы, рисунки, умные чипы, комментарии, заметки, вставка функций, ИИ. Скрипты не нужны с самого начала. Вставка картинок остаётся в требованиях.

Формулы нужны (решение владельца): движок формул входит в открытую часть редактора. Не нужен только пункт меню «вставить функцию» — формулы вводятся в ячейку и в строку формул.

### 17.2 Решение: Univer, открытая часть

При таком объёме отдельный тяжёлый сервис (Collabora, ONLYOFFICE) не нужен. Берём **Univer** — библиотеку под лицензией Apache 2.0, которая встраивается прямо в сайт. Всё, что требуется, есть в её открытой части, без водяных знаков и без чужих логотипов:

- ячейки, оформление, шрифты, заливки, границы, объединение, перенос текста, форматы чисел и дат;
- несколько листов в таблице, закрепление строк и столбцов, размеры, скрытие;
- проверка данных: выпадающий список (в том числе с цветами), флажок, дата, число;
- сортировка, фильтры, поиск и замена, условное форматирование;
- картинки — плавающие и внутри ячеек;
- копирование и вставка из Google Sheets и Excel с оформлением, отмена и повтор, автозаполнение;
- тёмная тема, русский язык интерфейса.

Платные части Univer (диаграммы, сводные, обмен `.xlsx`, печать, одновременное редактирование) не подключаются вовсе — с ними и приходят водяные знаки. Лишние пункты меню и кнопки (комментарии, заметки, мастер функций) убираются: редактор собирается из модулей, ненужные просто не ставятся.

Почему не остальные: ONLYOFFICE — логотип не убирается по лицензии; Collabora — отдельный сервис с 1,3 ГБ памяти ради возможностей, которые не нужны; Luckysheet — заброшен; свой редактор с нуля — месяцы работы.

### 17.3 Как это выглядит

- Пункт меню «Таблицы» в группе «Игрокам», адрес `/tables` — список таблиц без предпросмотра (решение владельца от 4 октября вместо подвкладок). Таблица открывается на своей странице `/tables/<адрес>`; листы — вкладками снизу.
- Гость без входа видит ту же страницу в публичной рамке (как юридические страницы): шапка, подвкладки, таблица только для просмотра — можно листать и переключать листы; выделение, копирование, поиск и контекстное меню отключены. Это ограничение интерфейса: данные таблицы всё равно приходят в браузер, и технически подкованный посетитель их достанет.
- Администратор видит справа сверху кнопку «Редактировать»: появляется панель инструментов. Изменения сохраняются сами; рядом — «Сохранено» / «Сохраняется…» и кнопка «Готово».
- Создание, загрузка из `.xlsx` и порядок таблиц — на странице списка; переименование, история версий и архив — на странице самой таблицы, в меню рядом с «Редактировать». Ничего не удаляется физически.
- Оформление редактора — под сайт: тёмная тема, акцентный цвет, шрифт Montserrat в списке шрифтов.

### 17.4 Данные и сервер

- Таблица `sheet_documents`: адрес, название, порядок, статус, снимок книги (JSON), номер версии, кто и когда изменил.
- Таблица `sheet_revisions`: снимок на момент завершения сеанса редактирования — история, к которой можно вернуться. Не чаще одной записи в 10 минут на таблицу.
- Картинки не хранятся внутри снимка: при вставке файл уходит в существующее хранилище (S3, лимит 10 МБ, проверка типа), в снимке остаётся адрес. Для гостей — отдельный адрес выдачи, который отдаёт только файлы, привязанные к таблицам.
- API: чтение снимка — открыто всем (с кэшем и учётом аварийной блокировки); запись — «Админ» и выше, с записью в журнал аудита (без самого снимка: размер и номер версии).
- Двое редактируют одну таблицу: редактирует один. Кнопка «Редактировать» берёт блокировку («сейчас редактирует Ник»), она снимается по «Готово» или через несколько минут без активности; сохранение проверяет номер версии.
- Ограничения: размер снимка (например, 5 МБ), число таблиц; общий лимит записи уже стоит в `middleware.ts`.
- Отдельных служб на сервере не добавляется; развёртывание не меняется.

### 17.6 Риски

- **React 19:** Univer с ним работает, но выдаёт предупреждения; редактор подключается только на клиенте. Проверяется на этапе 0.
- **Вес:** редактор — несколько мегабайт скриптов. Грузится только на странице таблиц.
- **Телефон:** просмотр работает, редактирование с телефона неудобное — рассчитывать на компьютер.
- **Открытый доступ:** страница без входа — мишень для нагрузки. Нужны кэш снимка и ограничение размера; запись закрыта правами.
- **Точность вида:** цветные плашки списка и флажки в Univer выглядят похоже на Google Sheets, но не один в один; сверяется на пробе по образцам.
- **Зависимость от редактора:** формат снимка — формат Univer. Запасной вариант, если проба не пройдёт, — FortuneSheet (MIT).

### 17.9 Доступ к таблице (4 октября 2026)

У каждой таблицы свой уровень доступа, меняется в меню таблицы → «Доступ»:

- **Открытая** — видят все, в том числе без входа (так создаётся новая таблица).
- **По списку** — видят только вошедшие через Discord, чей ID внесён в список (аналог доступа по почте в Google). Гостя отправляет на вход.
- **Закрытая** — видят только администраторы («Админ» и выше).

Администраторы видят и правят все таблицы. Таблица без доступа отвечает как несуществующая — и страница, и книга, и её картинки; в списке её нет.

### 17.8 Что получилось и что не проверено

Сделано иначе, чем в плане:

- **Лист белый, панели тёмные.** Тёмная тема Univer инвертирует цвета ячеек, из-за чего перенесённые таблицы перекрашивались. Инверсия отключена: ячейки рисуются ровно теми цветами, что заданы, незаполненная ячейка — белая с тёмным текстом, как в Google Sheets; панели редактора остались тёмными.
- **Лишние сохранения не отправляются.** Перед отправкой книга сравнивается с последней сохранённой; открытие редактора без правок ничего не меняет.
- **Импорт `.xlsx`** не переносит картинки, условное форматирование и цвета плашек выпадающих списков (в файле их нет в пригодном виде) — их настраивают заново в редакторе.
- **Формулы включены**, вкладка «Формулы» в панели редактора оставлена.

Не проверено:

- **Всё, что требует входа администратора**, в браузере не проверялось — встроенный браузер разлогинен: кнопка «Редактировать», автосохранение, блокировка, «Готово», переименование, история и возврат версии, архив, создание и загрузка `.xlsx` через страницу, вставка картинки. Логика сохранения, блокировки, истории и импорта покрыта тестами ядра; редактор в режиме правки проверен на временной странице без сервера (ввод текста, формула).
- Гостевой просмотр проверен: список, таблица, переключение листов, вид импортированной таблицы.
- Уровни доступа проверены гостем: открытая таблица видна, «по списку» и закрытая отправляют на вход, их книги отвечают 404, запись без входа — 401. Вошедший не из списка и окно «Доступ» в браузере не проверялись.
- Читаемость текста на плашках выпадающего списка при тёмной заливке ячейки.
- Вид на телефоне.
