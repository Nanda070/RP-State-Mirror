# Mirror: этап 4 — новые модули бота

Статус: **✅ закрыт** (2026-10-03).

## Цель

Добавить пользовательские и служебные модули поверх этапов 1–3: персонажи и статики, нашивки, регистрации ТС и униформы, переводы между фракциями, запрос webhook, IC чёрный список, служебные утилиты, панели ролей, обратная связь, формы внутри Discord.

## Схема данных

Миграции этапа 4:

- `20261003060000_stage4_modules` — characters, tokens, registrations, media_files, transfers, webhook_requests, ic_blacklist, role_panels, feedback, forms;
- `20261003070000_stage4_registrations`, `20261003080000_stage4_transfers` — доработки регистраций/переводов;
- `20261003090000_form_delivery_channel` — доставка ответа формы в канал;
- `20261003100000_ic_blacklist_gov` — IC ЧС как ордер GOV: `number`, `forum_link`, close flow, связь с `sent_message_links`.

Частичные индексы Prisma-схемой не выражаются и заданы в SQL миграции. При генерации следующих миграций `prisma migrate dev` может предложить их удалить — такие строки из сгенерированного SQL нужно убирать.

## Сделано

- `/нашивка получить|список|найти|снять` (нашивка = только номер; персонаж создаётся автоматически по статику при «получить»);
- slash `/персонаж` убран — пользовательских команд управления персонажами нет;
- `/регистрация-тс`, `/регистрация-формы` (§4.5–4.6);
- `/перевод-фракции` (§4.8);
- `/создать-вебхук` (§4.7) + очередь запросов и webhook URL в `/settings/stage4`;
- IC чёрный список (§4.13): `/чс-гос`, `/снятие-чс-гос`, `/чс-найти`;
  - пользователь вводит ФИО / паспорт / причину / ссылку на форум;
  - система выдаёт **Номер** (`BL-###`) и **Статус**;
  - embed цвета `15158332`, author «Издал ордер: …», footer как у gov-модулей;
  - публикация/правка сообщения через jobs (аналог розыска);
  - роли `icBlacklist.managerRoleIds` / `searchRoleIds`, канал `icBlacklist.channelId`, реестр в дашборде;
  - пометка в профиле дашборда при совпадении паспорта со статиком;
- `/проверить-фракции`, `/инвайт-админ` (§4.11);
- §4.14 панели ролей, формы (до 5 полей), обратная связь;
- button-manager: `role.toggle`, `form.open`, `feedback.open`, `token.receive`;
- `/settings/stage4`, `/settings/tokens`, `/settings/registrations`, `/settings/buttons`.
