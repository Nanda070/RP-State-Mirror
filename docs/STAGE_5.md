# Mirror: этап 5 — разделы для игроков и формы

Статус: **в работе** (старт 2026-10-03).

## Цель

Дать игроку собственные разделы дашборда (каталог ТС, калькулятор переводов, FAQ, профиль с персонажами и заявками), собрать полноценный конструктор форм с публичными страницами и ввести публичные ссылки на записи реестров.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Каталог ТС и `/регистрация-тс` | Каталог **только справочный**: модель в команде остаётся свободным текстом, каталог на команду не влияет |
| Таблица рангов переводов | **Попарные правила**: строка «фракция A, ранг N → фракция B, ранг M». Пустая пара — перевод без проверки ранга |
| Восстановление аккаунта | **Не делаем** (решение от 2026-10-03): раздел был реализован и убран. Перенос персонажа на другой аккаунт — ручная операция админа (PLAN §14.4 п.7) |
| Антиспам публичных форм | Cloudflare Turnstile + лимит отправок с IP + блокировка IP + срок жизни и лимит ответов. Ключи `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` в `.env`; без ключей капча выключена, остальное работает |
| Публичные ссылки | Розыск, IC ЧС, штрафы, документы, регистрации ТС и униформы |
| Профиль игрока | Входит в этап 5: персонажи, нашивки, регистрации, штрафы, розыски, пометка IC ЧС (только чтение) |
| Типы полей форм | Короткий текст, абзац, число, выбор одного, выбор нескольких, флажок, дата. Загрузки файлов нет |
| Git | Один коммит в `main` на законченный блок после зелёных `check` / `lint` / `test`, без push |

Общее правило: любые роли выбираются в дашборде, списков ролей в коде и `.env` нет.

## Блоки

### 1. Доступ игрока и навигация
- Боковое меню показывает игроку группу «Игрокам» (каталог, калькулятор, FAQ); админские разделы видны только по правам.
- Middleware защищает новые разделы.

### 2. Каталог ТС (§5.3)
- Страница `/catalog`: карточки с фото, марка, год, поиск, фильтр по марке, «скопировать название».
- Редактирование (уровень «Админ» и выше): создать, изменить, архивировать, загрузить фото (S3, до 10 МБ, PNG / JPEG / WEBP).
- Фото отдаётся через дашборд по идентификатору файла, прямых ссылок на хранилище нет.

### 3. Калькулятор переводов (§5.3)
- Страница `/transfers/calculator`: выбрать фракции «из» и «в», увидеть соответствие рангов.
- Редактор правил (главный админ): добавить, изменить, удалить правило, массовое заполнение пары.
- `/перевод-фракции` уже проверяет ранг по этой таблице.

### 4. FAQ и документация (§5.3)
- Разделы и статьи, Markdown, порядок, поиск.
- Чтение — любой вошедший; редактирование — «Хелпер» и выше.

### 5. Профиль игрока (§5.4)
- Вкладки: обзор, персонажи и нашивки, регистрации, штрафы и розыск, фракции и роли.
- Пометка «в IC чёрном списке», если паспорт совпадает со статиком персонажа.

### 6. Конструктор форм (§5.5, §5.10)
- Одна сущность формы для Discord и веба: поля расширенных типов, обязательность, валидация (мин/макс длина, диапазон числа, варианты выбора).
- Редактирование формы после создания; просмотр и экспорт ответов.
- Публичная страница `/f/<slug>` без входа; ответ уходит в канал и/или вебхук.
- Антиспам: Turnstile, лимит с IP, блокировка IP, срок жизни, лимит ответов.
- Discord: формы длиннее 5 полей открываются несколькими шагами модалки; в Discord доступны только текстовые типы, остальные — на веб-странице.

### 7. Публичные ссылки (§5.8)
- Кнопка «поделиться» в реестрах розыска, IC ЧС, штрафов, документов, регистраций.
- Страница `/s/<token>` без входа: краткая карточка; ссылку можно отозвать, отозванная отдаёт 404.

### 8. Панели ролей (перенос из этапа 4 и §14.4 п.1)
- Страница кнопок возвращается в дашборд: `role.toggle`, `callback`, публикация и архив панелей.
- Выпадающий список ролей как альтернатива кнопкам.

## Критерии закрытия

- Каждый блок доступен из дашборда без правки БД вручную.
- Все изменения данных идут через `auditedMutation`.
- Права проверяются на сервере в каждом API-маршруте.
- На каждый блок есть интеграционные тесты ядра.
- `pnpm check`, `pnpm lint`, `pnpm test`, `pnpm build` — зелёные.
