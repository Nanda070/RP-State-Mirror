# Mirror: этап 5 — разделы для игроков и формы

Статус: **✅ закрыт** (2026-10-03).

## Цель

Дать игроку собственные разделы дашборда (каталог ТС, калькулятор переводов, FAQ, профиль с персонажами и заявками), собрать полноценный конструктор форм с публичными страницами и ввести публичные ссылки на записи реестров.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Каталог ТС и `/регистрация-тс` | Каталог **только справочный**: модель в команде остаётся свободным текстом, каталог на команду не влияет |
| Таблица рангов переводов | **Попарные правила**: строка «фракция A, ранг N → фракция B, ранг M». Пустая пара — перевод без проверки ранга |
| Восстановление аккаунта | **Не делаем** (решение от 2026-10-03): раздел был реализован и убран. Перенос персонажа на другой аккаунт — ручная операция админа (PLAN §14.4 п.7) |
| Антиспам публичных форм | Капча, лимит с IP и блокировка IP **не делаются** (решение от 2026-10-03): были реализованы и убраны. Остаются срок жизни и лимит ответов формы |
| Публичные ссылки | Розыск, IC ЧС, штрафы, документы, регистрации ТС и униформы |
| Профиль игрока | Входит в этап 5: персонажи, нашивки, регистрации, штрафы, розыски, пометка IC ЧС (только чтение) |
| Типы полей форм | Короткий текст, абзац, число, выбор одного, выбор нескольких, флажок, дата. Загрузки файлов нет |
| Git | Один коммит в `main` на законченный блок после зелёных `check` / `lint` / `test`, без push |

Общее правило: любые роли выбираются в дашборде, списков ролей в коде и `.env` нет.

## Схема данных

- `20261003130000_stage5_player_sections` — фото в `vehicle_models`; `faq_sections`, `faq_items`; публичные настройки форм (`slug`, `public_enabled`, `success_message`); типы и варианты полей (`options`, `help_text`, `status`); `form_drafts`, `share_links`.
- `20261003140000_drop_account_recovery` — удаляет таблицу отменённого раздела восстановления.
- `20261003150000_drop_form_antispam` — удаляет блокировки IP, настройки капчи и лимита, а также IP и user-agent из ответов форм.

Частичный уникальный индекс задан в SQL: одна активная ссылка на запись.

## Сделано

### 1. Доступ игрока и навигация
- Боковое меню и Ctrl+K показывают пункты по правам: группа «Игрокам» — всем, реестры — «Хелпер» и выше, настройки — главному админу.
- Главная страница: сотрудник видит системные показатели, игрок — свои разделы.
- Middleware защищает все разделы, включая ранее пропущенные `/personnel`, `/feedback`, `/ic-blacklist`.

### 2. Каталог ТС — `/catalog`
- Карточки с фото, маркой и годом; поиск, фильтр по марке, «скопировать».
- Редактирование («Админ» и выше): создать, изменить, убрать в архив, загрузить фото.
- Фото: тип определяется по содержимому файла, а не по заголовку запроса; до 10 МБ; отдаётся через `/api/media/<id>`, адрес хранилища в браузер не попадает.

### 3. Калькулятор переводов — `/calculator`
- Выбор пары фракций и ранга, результат и вся таблица пары.
- Редактор таблицы пары (главный админ): строки, «заполнить 1 → 1», очистка. Сохранение заменяет таблицу целиком; изменённые и убранные правила уходят в архив.
- `/перевод-фракции` проверяет ранг по этой же таблице.

### 4. FAQ — `/faq`
- Разделы и статьи в Markdown, порядок стрелками, поиск по заголовку и тексту, предпросмотр в редакторе.
- Редактирование — «Хелпер» и выше.
- Markdown разбирается собственным небольшим парсером в дерево и рисуется элементами React: HTML из текста показывается как текст, ссылки — только `http(s)`.

### 5. Профиль игрока — `/profile`
- Вкладки: обзор, персонажи и нашивки, регистрации и переводы, штрафы и розыск, фракции и серверы.
- Штрафы, розыски и IC ЧС подбираются по статикам персонажей игрока.

### 6. Конструктор форм — `/settings/forms`
- Одна форма для Discord и веба: 7 типов полей, обязательность, подсказки, варианты, ограничения длины и диапазона, до 25 полей.
- Редактирование после создания: поля сопоставляются по ключу, убранные уходят в архив, старые ответы сохраняют подписи.
- Ответы: таблица с пагинацией и выгрузка CSV (значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются).
- Публичная страница `/f/<адрес>` без входа. Ограничения: срок и лимит ответов формы; запрос с чужого сайта отклоняется, есть скрытое поле-ловушка для простых ботов. IP отправителя не сохраняется.
- Discord: формы длиннее 5 полей заполняются в несколько шагов (черновик хранится в `form_drafts`); формы с полями выбора кнопка в Discord отправляет на веб-страницу.
- Вебхук формы принимается только вида `https://discord.com/api/webhooks/…`.
- Адрес сайта для ссылок бота — переменная `PUBLIC_BASE_URL` в `.env` (по умолчанию `http://localhost:3000`; заменить, когда появится домен).

### 7. Публичные ссылки — `/s/<токен>`
- Кнопка «Поделиться» в реестрах розыска, IC ЧС, штрафов, документов и регистраций («Админ» и выше): создаёт ссылку, копирует её, позволяет отозвать.
- Карточка без входа: только краткие сведения — без Discord ID и ссылок на форум. Фото регистрации показывается, только пока регистрация одобрена.
- Отозванная ссылка отвечает 404. Токен в журнал аудита не пишется.

### 8. Панели ролей — `/settings/buttons`
- Создание панели: сервер, канал, заголовок, текст, цвет, роли из снимка сервера; вид — кнопки или выпадающий список; «только одна роль»; ограничение, кто может пользоваться.
- Список панелей: обновить сообщение, убрать в архив.
- Выпадающий список работает как «набор»: отмеченные роли выдаются, остальные из списка снимаются.

## Проверка

- `pnpm check`, `pnpm test` — зелёные (27 файлов, 189 тестов).
- `pnpm lint` — единственная ошибка в `login-backdrop.tsx`, файле параллельной работы над страницей входа; код этапа 5 проходит.
- Публичная форма и публичная ссылка проверены на запущенном dev-сервере: отправка, ошибка валидации, чужой источник (403), ловушка, 404 после архива и отзыва.
- **Не проверено глазами:** страницы за входом (каталог, калькулятор, FAQ, профиль, конструктор, панели ролей) — для них нужна сессия Discord. Они проходят проверку типов; перед запуском их нужно пройти вручную.
- **Не запускался** `next build`: во время работы был запущен dev-сервер, сборка в ту же папку `.next` сломала бы его.
- Обработчики бота (многошаговые формы, выпадающий список ролей) собираются, но в Discord не прогонялись.

## Что нужно сделать после обновления

1. Перезапустить бота из свежей сборки (`pnpm --filter @mirror/bot build`, затем запуск): запущенный процесс не знает о новых задачах и обработчиках.
2. Когда появится домен — задать `PUBLIC_BASE_URL` в `.env` и перезапустить бота и дашборд.
